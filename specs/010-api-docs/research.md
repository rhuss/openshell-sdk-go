# Research: API Documentation Site

## mdBook Configuration

**Decision**: Use mdBook v0.4+ with mdbook-admonish preprocessor.

**Rationale**: mdBook is a single binary with no runtime dependencies.
The admonish preprocessor adds callout boxes (tip, warning, note) that
significantly improve documentation readability. Both are installable
via GitHub Actions with no npm/pip/cargo required in CI.

**Alternatives considered**:
- MkDocs Material: More polished, native content tabs, but requires Python
  in CI and adds dependency complexity.
- Hugo + Doks: Go-native but most complex setup, theme quality varies.
- Docsify: Zero-build but poor SEO, limited to 4 themes.

## Typography Approach

**Decision**: Load Inter font from Google Fonts CDN, override mdBook
defaults via `docs/theme/custom.css`.

**Rationale**: Inter is a modern sans-serif font designed for screens,
widely used in developer tooling (GitHub, Vercel, Linear). Google Fonts
CDN provides reliable global distribution with no self-hosting burden.

**Alternatives considered**:
- System-ui only: Varies across platforms, inconsistent appearance.
- Self-hosted font files: Adds files to repo, requires maintenance.
- Bunny Fonts: Privacy-friendly alternative but less reliable CDN.

**Implementation**: Override `:root` CSS variables in mdBook's theme
system. mdBook supports a `theme/` directory for custom CSS that's
loaded after the default styles.

## gRPC Side-by-Side Display

**Decision**: Sequential labeled code blocks for hero interfaces,
markdown tables for non-hero interfaces.

**Rationale**: mdBook has no native tab widget. Sequential blocks with
bold labels ("SDK (Go):" / "gRPC (Proto):") are clear and readable.
The mdbook-tabs preprocessor exists but is unmaintained and may break
with future mdBook versions.

**Alternatives considered**:
- mdbook-tabs: Unmaintained preprocessor, risk of breakage.
- Custom JavaScript: Adds complexity, breaks mdBook's simplicity.
- HTML tables with code blocks: Renders poorly in markdown.

## Example* Test Functions

**Decision**: Use the fake client package to make all Example* functions
compilable without a live gateway.

**Rationale**: Go Example* functions must compile and optionally produce
output. Using the fake client allows examples to demonstrate real SDK
patterns (Create, WaitReady, Watch) without network dependencies. The
fake package already implements the full ClientInterface.

**Implementation**: Two test files:
- `example_test.go`: Examples for core SDK operations (NewClient pattern
  shown with Config struct, all sub-client operations use fake).
- `example_fake_test.go`: Examples specifically for the fake package
  (fixture seeding, watch events, health simulation).

## GitHub Pages Deployment

**Decision**: Dedicated `docs.yml` workflow, separate from the existing
`ci.yml`.

**Rationale**: Documentation builds should not block code CI. A separate
workflow allows path-filtered triggers (only rebuild on docs/ changes)
and independent failure handling.

**Implementation**: Use `peaceiris/actions-gh-pages@v4` for deployment.
The action handles branch creation, force-push to gh-pages, and cache
management. mdBook is installed via `peaceiris/actions-mdbook@v2`.

## Default Theme

**Decision**: Light theme as default.

**Rationale**: Widest audience, matches the "clean" aesthetic goal. mdBook
includes Light, Rust, Coal, Navy, and Ayu themes, and users can switch
freely. Light is the most readable for code-heavy documentation.

## mdbook-admonish

**Decision**: Include mdbook-admonish preprocessor for callout boxes.

**Rationale**: Callout boxes (tip, warning, note, important) are essential
for documentation that guides developers through error-prone steps. The
preprocessor is actively maintained and widely used in the mdBook
ecosystem.

**Implementation**: Add `[preprocessor.admonish]` to book.toml. CSS is
auto-generated by `mdbook-admonish install`.
