# Feature Specification: Policy Management, Logs, MergeOperations, and ErrorConflict (Phase 2b-2)

**Feature Branch**: `008-policy-logs`
**Created**: 2026-06-29
**Status**: Draft
**Input**: Phase 2b-2 SDK extension: policy draft-review-approve workflow (10 RPCs), sandbox log retrieval, typed policy merge operations for config updates, and optimistic concurrency error code.

## User Scenarios & Testing

### User Story 1 - Operator Reviews and Approves Draft Policy Chunks (Priority: P1)

An operator managing sandbox security policies needs to review proposed policy changes (draft chunks generated by the gateway's policy analysis engine), approve or reject individual chunks, and see the resulting policy version after approval. The draft-review-approve workflow is the core policy management loop.

**Why this priority**: The draft chunk workflow is the primary interaction model for policy management. Without it, operators have no way to review or control AI-proposed policy changes through the SDK.

**Independent Test**: Get draft policy for a sandbox, verify chunks are returned with status/rationale/proposed_rule. Approve a chunk, verify a new policy version and hash are returned. Reject a chunk with a reason, verify success. Get draft again, verify chunk statuses reflect the decisions.

**Acceptance Scenarios**:

1. **Given** a sandbox "prod-agent" with pending draft chunks, **When** the operator calls Policy().GetDraft with sandbox name "prod-agent", **Then** a DraftPolicy is returned containing chunks (each with ID, status, rule_name, proposed_rule, rationale), a draft version, and last analyzed timestamp.
2. **Given** a pending draft chunk with ID "chunk-abc", **When** the operator calls Policy().ApproveDraftChunk with sandbox "prod-agent" and chunk ID "chunk-abc", **Then** an ApproveResult is returned with the new policy version and policy hash.
3. **Given** a pending draft chunk with ID "chunk-def", **When** the operator calls Policy().RejectDraftChunk with sandbox "prod-agent", chunk ID "chunk-def", and reason "too broad", **Then** the call succeeds (no error).
4. **Given** no sandbox "missing" exists, **When** the operator calls Policy().GetDraft with sandbox "missing", **Then** a NotFound error is returned.

### User Story 2 - Operator Bulk-Approves or Clears Draft Chunks (Priority: P1)

An operator who trusts the analysis engine wants to approve all pending chunks at once, optionally including security-flagged chunks. Alternatively, they may want to clear all pending chunks to start fresh. After bulk approval, they check the decision history.

**Why this priority**: Bulk operations and history are essential for governance workflows. Approving chunks one-by-one is impractical when dozens are pending.

**Independent Test**: Approve all chunks (excluding security-flagged), verify chunks_approved and chunks_skipped counts. Approve all with WithIncludeSecurityFlagged(), verify all are approved. Clear chunks, verify chunks_cleared count. Get history, verify entries reflect the operations.

**Acceptance Scenarios**:

1. **Given** a sandbox "prod-agent" with 5 pending chunks (2 security-flagged), **When** the operator calls Policy().ApproveAllDraftChunks with sandbox "prod-agent" (no options), **Then** an ApproveAllResult is returned with chunks_approved=3, chunks_skipped=2, new policy version, and policy hash.
2. **Given** the same sandbox, **When** the operator calls Policy().ApproveAllDraftChunks with WithIncludeSecurityFlagged(), **Then** chunks_approved=5, chunks_skipped=0.
3. **Given** a sandbox with pending chunks, **When** the operator calls Policy().ClearDraftChunks with sandbox "prod-agent", **Then** a ClearResult is returned with the count of chunks cleared.
4. **Given** a sandbox with policy decision history, **When** the operator calls Policy().GetDraftHistory with sandbox "prod-agent", **Then** a list of DraftHistoryEntry items is returned, each with timestamp, event_type, description, and optional chunk_id.

### User Story 3 - Operator Inspects Policy Status and History (Priority: P2)

An operator needs to check whether the latest policy version has been loaded by the sandbox, list previous policy revisions, and edit a pending chunk before approving it. They also need to undo a previously approved chunk if it causes issues.

**Why this priority**: Status monitoring and edit/undo are needed for operational control but are less frequent than the approve/reject cycle.

**Independent Test**: Get policy status for a sandbox, verify revision details and active version. List policy revisions, verify multiple revisions are returned. Edit a chunk's proposed rule, verify success. Undo an approved chunk, verify new policy version is returned.

**Acceptance Scenarios**:

1. **Given** a sandbox "prod-agent" with policy version 3 loaded, **When** the operator calls Policy().GetStatus with sandbox "prod-agent", **Then** a PolicyStatusResult is returned containing the queried revision (version, hash, status, timestamps) and the active version (3).
2. **Given** a sandbox with multiple policy revisions, **When** the operator calls Policy().List with sandbox "prod-agent", **Then** a list of SandboxPolicyRevision items is returned with version, hash, status, and timestamps.
3. **Given** a pending chunk "chunk-xyz", **When** the operator calls Policy().EditDraftChunk with a modified NetworkPolicyRule, **Then** the call succeeds (no error).
4. **Given** an approved chunk "chunk-abc", **When** the operator calls Policy().UndoDraftChunk with sandbox "prod-agent" and chunk ID "chunk-abc", **Then** an UndoResult is returned with the new policy version and hash after the rule was removed.

### User Story 4 - Developer Retrieves Sandbox Logs (Priority: P2)

A developer debugging a sandbox needs to retrieve recent log lines. They can filter by time range, log source (gateway vs sandbox), minimum severity level, and line count. The SDK accepts the sandbox name and resolves the sandbox ID internally.

**Why this priority**: Log retrieval is a single RPC with clear utility for debugging, but it's supplementary to the core policy management workflow.

**Independent Test**: Get logs for a sandbox, verify log lines are returned with timestamps, level, message, source, and fields. Filter with WithLogMinLevel("WARN"), verify only WARN+ lines returned. Filter with WithLogSources("sandbox"), verify only sandbox-sourced lines. Get logs for a non-existent sandbox, verify NotFound error.

**Acceptance Scenarios**:

1. **Given** a sandbox "debug-env" with log history, **When** the developer calls Sandboxes().GetLogs with sandbox name "debug-env", **Then** a LogResult is returned containing log lines (each with timestamp, level, target, message, source, fields map) and a buffer total count.
2. **Given** a sandbox with logs at various levels, **When** the developer calls GetLogs with WithLogMinLevel("WARN"), **Then** only WARN and ERROR lines are returned.
3. **Given** a sandbox with logs from multiple sources, **When** the developer calls GetLogs with WithLogSources("sandbox"), **Then** only sandbox-sourced lines are returned.
4. **Given** a sandbox with many logs, **When** the developer calls GetLogs with WithLogLines(50), **Then** at most 50 lines are returned.
5. **Given** no sandbox "missing" exists, **When** the developer calls GetLogs with sandbox name "missing", **Then** a NotFound error is returned.

### User Story 5 - Operator Uses Typed Merge Operations in Config Updates (Priority: P2)

An operator needs to make incremental policy changes through config updates using structured merge operations (add a network rule, remove an endpoint, add deny rules, etc.) instead of replacing the entire policy blob. The SDK provides typed structs for each operation variant.

**Why this priority**: Merge operations enable fine-grained policy edits without full policy replacement. The previous implementation used opaque bytes and rejected them at runtime. This unblocks the feature.

**Independent Test**: Create a ConfigUpdate with a PolicyMergeOperation containing an AddNetworkRule, call Config().Update, verify it succeeds and returns a new version. Create an update with RemoveNetworkEndpoint, verify success. Create an update with an invalid operation (all fields nil), verify an InvalidArgument error.

**Acceptance Scenarios**:

1. **Given** a sandbox "worker-1", **When** the operator calls Config().Update with MergeOperations containing an AddNetworkRule (rule_name + NetworkPolicyRule), **Then** a ConfigUpdateResult is returned with a new policy version and hash.
2. **Given** a sandbox with an existing rule "allow-github", **When** the operator calls Config().Update with MergeOperations containing RemoveNetworkRule{RuleName: "allow-github"}, **Then** the update succeeds and returns a new policy version.
3. **Given** a ConfigUpdate with MergeOperations containing a PolicyMergeOperation where all variant fields are nil, **When** Config().Update is called, **Then** an InvalidArgument error is returned.

### User Story 6 - Developer Handles Optimistic Concurrency Conflicts (Priority: P3)

A developer using Config().Update with an expected_resource_version encounters a version mismatch because another client modified the sandbox config concurrently. The SDK returns a typed ErrorConflict error that the developer can detect with IsConflict() and use to implement a read-modify-write retry loop.

**Why this priority**: Optimistic concurrency is critical for correctness but only affects multi-client scenarios. The error code fix is small and enables callers to handle conflicts programmatically instead of treating them as internal errors.

**Independent Test**: Call Config().Update with an outdated expected_resource_version, verify the error is a StatusError with Code=ErrorConflict. Verify IsConflict(err) returns true. Verify IsConflict on other error types returns false.

**Acceptance Scenarios**:

1. **Given** a sandbox with resource_version=5, **When** the developer calls Config().Update with expected_resource_version=3, **Then** a StatusError with Code=ErrorConflict is returned.
2. **Given** an ErrorConflict error, **When** the developer calls types.IsConflict(err), **Then** true is returned.
3. **Given** an ErrorNotFound error, **When** the developer calls types.IsConflict(err), **Then** false is returned.
4. **Given** a nil error, **When** the developer calls types.IsConflict(nil), **Then** false is returned.

### User Story 7 - Fake Client Stubs for Testing (Priority: P3)

A developer writing tests for code that uses the PolicyInterface or the extended SandboxInterface (with GetLogs) needs fake implementations that compile against the updated interfaces. Fake stubs return Unimplemented errors. The fake ConfigClient is updated to support MergeOperations (no longer rejects them at runtime).

**Why this priority**: The fake client must compile with the updated interfaces. Stubs returning Unimplemented are sufficient for consumers who mock these interfaces directly.

**Independent Test**: Create a fake client, call Policy().GetDraft, verify Unimplemented error. Call Sandboxes().GetLogs, verify Unimplemented error. Call Config().Update with MergeOperations, verify it no longer returns an error (merge ops are accepted by the fake). Verify the fake client compiles against ClientInterface.

**Acceptance Scenarios**:

1. **Given** a fake client, **When** the developer calls Policy().GetStatus, **Then** an Unimplemented error is returned.
2. **Given** a fake client, **When** the developer calls Policy().ApproveAllDraftChunks, **Then** an Unimplemented error is returned.
3. **Given** a fake client, **When** the developer calls Sandboxes().GetLogs, **Then** an Unimplemented error is returned.
4. **Given** a fake client, **When** the developer calls Config().Update with MergeOperations, **Then** no error is returned (merge operations accepted).
5. **Given** the updated ClientInterface with Policy() accessor, **When** a fake.Client is assigned to a ClientInterface variable, **Then** it compiles without errors.

### Edge Cases

- What happens when GetDraft is called with WithStatusFilter("invalid_status")? The server filters; SDK passes through and returns whatever the server returns (may be empty list).
- What happens when EditDraftChunk is called on an already-approved chunk? The server should reject it; SDK returns the server's error.
- What happens when ApproveAllDraftChunks is called with no pending chunks? The call succeeds with chunks_approved=0, chunks_skipped=0.
- What happens when GetLogs is called with WithLogLines(0)? The server uses its default (2000 lines per proto).
- What happens when GetLogs resolves sandbox name to ID but the sandbox was deleted between the Get and GetSandboxLogs calls? A NotFound error is returned from the GetSandboxLogs RPC.
- What happens when Config().Update is called with both MergeOperations and a full Policy blob? The server handles precedence; the SDK passes both fields through.

## Requirements

### Functional Requirements

**PolicyInterface (new top-level sub-client)**

- **FR-001**: SDK MUST provide a PolicyInterface with 10 methods as a top-level sub-client on ClientInterface, accessed via `client.Policy()`.
- **FR-002**: PolicyInterface.GetStatus MUST accept a context, sandbox name, and optional GetStatusOption functional options (WithVersion for querying a specific policy version; default 0 = latest), and return a PolicyStatusResult containing the queried SandboxPolicyRevision and the active policy version.
- **FR-003**: PolicyInterface.List MUST accept a context, sandbox name, and optional ListPolicyOption functional options (WithLimit for max results, WithOffset for pagination), and return a list of SandboxPolicyRevision items.
- **FR-004**: PolicyInterface.GetDraft MUST accept a context, sandbox name, and optional GetDraftOption functional options (WithStatusFilter), and return a DraftPolicy containing chunks, rolling summary, draft version, and last analyzed timestamp.
- **FR-005**: PolicyInterface.ApproveDraftChunk MUST accept a context, sandbox name, and chunk ID, and return an ApproveResult with new policy version and hash.
- **FR-006**: PolicyInterface.RejectDraftChunk MUST accept a context, sandbox name, chunk ID, and an optional reason string (empty string if no reason provided), and return no error on success. The reason is passed to the server for LLM context in future analysis cycles.
- **FR-007**: PolicyInterface.ApproveAllDraftChunks MUST accept a context, sandbox name, and optional ApproveAllOption functional options (WithIncludeSecurityFlagged), and return an ApproveAllResult with policy version, hash, chunks approved, and chunks skipped.
- **FR-008**: PolicyInterface.EditDraftChunk MUST accept a context, sandbox name, chunk ID, and a NetworkPolicyRule (the replacement rule), and return no error on success.
- **FR-009**: PolicyInterface.UndoDraftChunk MUST accept a context, sandbox name, and chunk ID, and return an UndoResult with new policy version and hash.
- **FR-010**: PolicyInterface.ClearDraftChunks MUST accept a context and sandbox name, and return a ClearResult with the count of chunks cleared.
- **FR-011**: PolicyInterface.GetDraftHistory MUST accept a context and sandbox name, and return a list of DraftHistoryEntry items.

**GetLogs (extension to SandboxInterface)**

- **FR-012**: SandboxInterface MUST be extended with a GetLogs method that accepts a context, sandbox name, and optional LogOption functional options.
- **FR-013**: GetLogs MUST resolve sandbox name to sandbox ID internally by calling Get(name) before issuing the GetSandboxLogs RPC.
- **FR-014**: GetLogs MUST return a LogResult containing log lines and a buffer total count.
- **FR-015**: LogOption functional options MUST include WithLogLines(n), WithLogSince(time.Time), WithLogSources(sources ...string), and WithLogMinLevel(level string).

**MergeOperations (update to ConfigUpdate)**

- **FR-016**: ConfigUpdate.MergeOperations MUST be changed from `[]byte` to `[]PolicyMergeOperation`.
- **FR-017**: PolicyMergeOperation MUST be a struct with exactly one non-nil pointer field set, representing the 6 proto oneof variants: AddRule (*AddNetworkRule), RemoveEndpoint (*RemoveNetworkEndpoint), RemoveRule (*RemoveNetworkRule), AddDenyRules (*AddDenyRules), AddAllowRules (*AddAllowRules), RemoveBinary (*RemoveNetworkBinary).
- **FR-018**: The converter MUST map between SDK PolicyMergeOperation structs and proto PolicyMergeOperation oneof variants in both directions.
- **FR-019**: The existing runtime rejection of MergeOperations in config_client.go and fake/config.go MUST be removed.

**ErrorConflict (new error code)**

- **FR-020**: A new ErrorConflict error code MUST be added to the ErrorCode enum in types/errors.go.
- **FR-021**: The error mapper MUST map gRPC codes.Aborted to types.ErrorConflict.
- **FR-022**: A new IsConflict(err) helper function MUST be added following the existing pattern.
- **FR-023**: FAILED_PRECONDITION MUST NOT be mapped to ErrorConflict; it continues to fall through to ErrorInternal.

**Domain types and cross-cutting**

- **FR-024**: All new domain types MUST be defined in `v1/types/` with no proto dependency.
- **FR-025**: All proto-to-SDK conversions MUST deep-copy maps, slices, and nested structs at boundaries.
- **FR-026**: All operations MUST be safe for concurrent use.
- **FR-027**: All operations MUST return typed StatusError with appropriate ErrorCode for error paths.
- **FR-028**: Fake client MUST implement Policy() accessor returning stubs that produce Unimplemented errors for all 10 methods.
- **FR-029**: Fake SandboxClient MUST implement GetLogs returning an Unimplemented error.
- **FR-030**: Fake ConfigClient MUST accept MergeOperations without error (remove the runtime rejection).
- **FR-031**: Fake client MUST pass the compile-time interface check (`var _ v1.ClientInterface = (*Client)(nil)`).
- **FR-032**: All converters MUST convert proto millisecond timestamps (int64) to time.Time in SDK types and vice versa. Zero time.Time maps to 0ms (meaning "no filter" or "not set").

### Key Entities

- **PolicyChunk**: A proposed policy rule with rationale and approval status. 18 fields: ID, Status (pending/approved/rejected), RuleName, ProposedRule (*NetworkPolicyRule), Rationale, SecurityNotes, Confidence (float32), DenialSummaryIDs ([]string), CreatedAt (time.Time), DecidedAt (time.Time), Stage (initial/refined), SupersedesChunkID, HitCount (int32), FirstSeen (time.Time), LastSeen (time.Time), Binary, ValidationResult, RejectionReason.
- **DraftPolicy**: Collection of draft chunks for a sandbox. Contains Chunks ([]PolicyChunk), RollingSummary, DraftVersion (uint64), LastAnalyzedAt (time.Time).
- **PolicyStatusResult**: Result of GetStatus. Contains Revision (SandboxPolicyRevision) and ActiveVersion (uint32).
- **SandboxPolicyRevision**: A versioned policy revision. Contains Version, PolicyHash, Status (PolicyLoadStatus), LoadError, CreatedAt (time.Time), LoadedAt (time.Time), Policy ([]byte, opaque).
- **PolicyLoadStatus**: Enum: Unspecified, Pending, Loaded, Failed, Superseded.
- **ApproveResult**: Result of ApproveDraftChunk. Contains PolicyVersion, PolicyHash.
- **ApproveAllResult**: Result of ApproveAllDraftChunks. Contains PolicyVersion, PolicyHash, ChunksApproved, ChunksSkipped.
- **UndoResult**: Result of UndoDraftChunk. Contains PolicyVersion, PolicyHash.
- **ClearResult**: Result of ClearDraftChunks. Contains ChunksCleared.
- **DraftHistoryEntry**: A decision history event. Contains Timestamp (time.Time), EventType, Description, ChunkID.
- **LogLine**: A sandbox log line. Contains Timestamp (time.Time), Level, Target, Message, Source, Fields (map[string]string).
- **LogResult**: Result of GetLogs. Contains Lines ([]LogLine), BufferTotal (uint32).
- **NetworkPolicyRule**: SDK representation of the sandbox proto type. Contains Name, Endpoints ([]NetworkEndpoint), Binaries ([]NetworkBinary).
- **NetworkEndpoint**: Full fidelity mapping of the sandbox.v1 proto. All 18 fields: Host, Port, Ports ([]uint32), Protocol, TLS, Enforcement, Access, Rules ([]L7Rule), AllowedIPs ([]string), DenyRules ([]L7DenyRule), AllowEncodedSlash (bool), PersistedQueries, GraphqlPersistedQueries (map[string]GraphqlOperation), GraphqlMaxBodyBytes (uint32), Path, WebsocketCredentialRewrite (bool), RequestBodyCredentialRewrite (bool), AdvisorProposed (bool).
- **L7Rule**: Contains Allow (*L7Allow).
- **L7Allow**: Method, Path, Command, Query (map[string]L7QueryMatcher), OperationType, OperationName, Fields ([]string).
- **L7DenyRule**: Method, Path, Command, Query (map[string]L7QueryMatcher), OperationType, OperationName, Fields ([]string).
- **L7QueryMatcher**: Glob (string), Any ([]string).
- **GraphqlOperation**: OperationType, OperationName, Fields ([]string).
- **NetworkBinary**: Path (string).
- **PolicyMergeOperation**: Struct with exactly one non-nil field: AddRule, RemoveEndpoint, RemoveRule, AddDenyRules, AddAllowRules, RemoveBinary.
- **AddNetworkRule**: RuleName + NetworkPolicyRule.
- **RemoveNetworkEndpoint**: RuleName + Host + Port.
- **RemoveNetworkRule**: RuleName.
- **AddDenyRules**: Host + Port + DenyRules ([]L7DenyRule).
- **AddAllowRules**: Host + Port + Rules ([]L7Rule).
- **RemoveNetworkBinary**: RuleName + BinaryPath.

## Clarifications

### Session 2026-06-29

- Q: Should GetStatus expose the proto `version` field for querying specific revisions? → A: Yes, as WithVersion functional option (default 0 = latest).
- Q: Should List expose pagination (proto has limit/offset)? → A: Yes, as WithLimit and WithOffset functional options.
- Q: Is RejectDraftChunk `reason` required or optional? → A: Optional (empty string = no reason). Passed to server for LLM context.
- Q: How deep to map NetworkPolicyRule type hierarchy? → A: Full fidelity. All 18 NetworkEndpoint fields, L7Rule, L7Allow, L7DenyRule, L7QueryMatcher, GraphqlOperation, NetworkBinary mapped 1:1.
- Q: How should time conversions work (proto uses ms-since-epoch, SDK uses time.Time)? → A: Converter handles all ms↔time.Time conversions. SDK types always use time.Time. Zero time.Time maps to 0ms (no filter).

## Assumptions

- The OpenShell gateway implements all 11 client-facing RPCs covered by this spec (10 policy RPCs + GetSandboxLogs).
- GetSandboxLogs uses sandbox_id (not name). The SDK resolves name→id via Sandboxes().Get() before calling the RPC.
- SandboxPolicy remains opaque bytes (`[]byte`) in the SandboxPolicyRevision type. Full policy domain mapping is out of scope.
- NetworkPolicyRule and related types (NetworkEndpoint, L7Rule, L7Allow, L7DenyRule, L7QueryMatcher, NetworkBinary) are mapped to SDK domain types in v1/types/ matching the sandbox.v1 proto structure.
- The existing Phase 1, Phase 2a, and Phase 2b-1 sub-clients, types, converters, and fake stubs remain unchanged (except Config which gains MergeOperations support and the error mapper which gains ErrorConflict).
- No new external dependencies are required.
- ListSandboxPolicies has a `global` flag in the proto. For v1, the SDK exposes sandbox-scoped listing only. Global policy listing can be added later if needed.
- GetSandboxPolicyStatus also has a `global` flag and a `version` field. The SDK passes through defaults (version=0 for latest, global=false).
