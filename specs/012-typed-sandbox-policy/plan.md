# Implementation Plan: Typed SandboxPolicy Domain Type

**Branch**: `012-typed-sandbox-policy` | **Date**: 2026-06-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/012-typed-sandbox-policy/spec.md`

## Summary

Introduce typed `SandboxPolicy`, `FilesystemPolicy`, `LandlockPolicy`,
and `ProcessPolicy` domain types. Replace opaque `[]byte` policy fields
with `*SandboxPolicy` in four locations: `SandboxSpec` (new field),
`ConfigUpdate`, `SandboxPolicyRevision`, and `SandboxConfig` (all
breaking changes from `[]byte`). Add converters with deep-copy
isolation, update fake client, and provide round-trip tests.

## Implementation Phases

### Phase 1: Domain Types (FR-001 through FR-007a)

Add the four new types to `openshell/v1/types/policy.go` and modify
the three existing types. This is the foundation that all other work
depends on.

**Files**: `types/policy.go`, `types/sandbox.go`, `types/setting.go`

**Changes**:
1. Add `SandboxPolicy` struct with doc comment (5 fields)
2. Add `FilesystemPolicy` struct with doc comment (3 fields)
3. Add `LandlockPolicy` struct with doc comment (1 field)
4. Add `ProcessPolicy` struct with doc comment (2 fields)
5. Add `Policy *SandboxPolicy` field to `SandboxSpec`
6. Change `ConfigUpdate.Policy` from `[]byte` to `*SandboxPolicy`
7. Change `SandboxPolicyRevision.Policy` from `[]byte` to `*SandboxPolicy`
8. Change `SandboxConfig.Policy` from `[]byte` to `*SandboxPolicy`

**Compilation note**: After this phase, existing converter code will
not compile (type mismatches). Phase 2 fixes this.

### Phase 2: Converters (FR-008 through FR-012a)

Add new converter functions and update existing ones to use typed
policy instead of `[]byte` marshal/unmarshal.

**Files**: `converter/policy.go`, `converter/sandbox.go`, `converter/setting.go`

**New functions in `policy.go`**:
- `SandboxPolicyFromProto(*sbv1.SandboxPolicy) *types.SandboxPolicy`
- `SandboxPolicyToProto(*types.SandboxPolicy) *sbv1.SandboxPolicy`
- `filesystemPolicyFromProto(*sbv1.FilesystemPolicy) *types.FilesystemPolicy`
- `filesystemPolicyToProto(*types.FilesystemPolicy) *sbv1.FilesystemPolicy`
- `landlockPolicyFromProto(*sbv1.LandlockPolicy) *types.LandlockPolicy`
- `landlockPolicyToProto(*types.LandlockPolicy) *sbv1.LandlockPolicy`
- `processPolicyFromProto(*sbv1.ProcessPolicy) *types.ProcessPolicy`
- `processPolicyToProto(*types.ProcessPolicy) *sbv1.ProcessPolicy`

Sub-type converters are unexported (only `SandboxPolicy` variants are
exported). `SandboxPolicyFromProto` iterates `network_policies` map
calling existing `NetworkPolicyRuleFromProto` per entry.

**Modified functions**:
- `sandboxSpecFromProto`: Add `SandboxPolicyFromProto(s.GetPolicy())`
- `SandboxSpecToProto`: Add `SandboxPolicyToProto(spec.Policy)`
- `SandboxPolicyRevisionFromProto`: Replace `proto.Marshal` + `CopyByteSlice`
  with `SandboxPolicyFromProto(r.GetPolicy())`
- `SandboxConfigFromProto`: Replace `proto.Marshal` with
  `SandboxPolicyFromProto(resp.GetPolicy())`
- `ConfigUpdateToProto`: Replace `proto.Unmarshal` with
  `SandboxPolicyToProto(cu.Policy)`. Remove error return path for
  invalid bytes (no longer applicable with typed input).

**Deep-copy strategy** (Constitution VII):
- `NetworkPolicies` map: allocate new map, iterate entries, deep-copy
  each `NetworkPolicyRule` value via existing converter round-trip
  or field-by-field copy.
- `ReadOnly`/`ReadWrite`: use `CopyStringSlice` from `copy.go`.
- Scalar fields (Version, IncludeWorkdir, Compatibility, RunAsUser,
  RunAsGroup): direct assignment (value types, no aliasing risk).

### Phase 3: Tests (FR-015, FR-016)

Add converter tests following the existing 3-pattern approach:
nil input, round-trip, deep-copy isolation.

**Files**: `converter/policy_test.go`, `converter/sandbox_test.go`,
`converter/setting_test.go`

**New tests in `policy_test.go`**:
- `TestSandboxPolicyFromProtoNil`
- `TestSandboxPolicyRoundTrip` (all fields populated, verify equality)
- `TestSandboxPolicyDeepCopy` (convert, mutate source, verify isolation)
- `TestFilesystemPolicyRoundTrip`
- `TestLandlockPolicyRoundTrip`
- `TestProcessPolicyRoundTrip`
- `TestSandboxPolicyPartialSubPolicies` (only some sub-policies set)

**Modified tests**:
- `TestSandboxSpecRoundTrip`: Add policy field to test fixture
- `TestSandboxPolicyRevisionFromProto`: Update to verify typed policy
  instead of bytes
- `TestConfigUpdateToProto`: Update to use typed policy instead of bytes
- `TestSandboxConfigFromProto`: Update to verify typed policy

### Phase 4: Fake Client (FR-013, FR-014)

Update the fake client to handle the new policy field.

**Files**: `fake/sandbox.go`, `fake/sandbox_test.go`

**Changes**:
- Add `copySandboxPolicy(*types.SandboxPolicy) *types.SandboxPolicy`
  helper with deep-copy of all fields including NetworkPolicies map
  and filesystem slices.
- Update `copySandboxSpec` to call `copySandboxPolicy` for the Policy
  field.
- Verify `fake/config.go` `Update` method works with typed policy
  (the existing config update stores the full `ConfigUpdate` struct,
  so the type change should propagate automatically).

**New test**:
- `TestFakeSandboxCreateWithPolicy`: Create sandbox with policy via
  fake, get it back, verify all policy fields match.
