# Implementation Plan: Sandbox Name Resolution

**Branch**: `013-sandbox-name-resolution` | **Date**: 2026-06-30 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/013-sandbox-name-resolution/spec.md`

## Summary

Unify the SDK's sandbox identifier API so all public methods accept
sandbox **name** and resolve to sandbox **ID** internally. This
follows the pattern already established by `SSH.Tunnel()`, extending
it to Exec, TCP, File, Config sub-clients, and fixing a bug in Watch
where a name is passed into a proto ID field.

## Design

### Reference Pattern: SSH.Tunnel()

The `sshClient` already demonstrates the exact pattern to replicate:

```go
type sshClient struct {
    client    pb.OpenShellClient
    sandboxes SandboxInterface  // injected dependency
}

func newSSHClient(conn grpc.ClientConnInterface, sandboxes SandboxInterface) *sshClient {
    return &sshClient{client: pb.NewOpenShellClient(conn), sandboxes: sandboxes}
}

func (s *sshClient) Tunnel(ctx context.Context, sandboxName string, ...) (...) {
    sandbox, err := s.sandboxes.Get(ctx, sandboxName)
    if err != nil { return nil, err }
    // use sandbox.ID in proto requests
}
```

Each affected sub-client (Exec, TCP, File, Config) will follow this
identical pattern: store `SandboxInterface`, resolve in each method.

### Watch Fix

`sandbox_client.go` already has a `sandboxClient` struct with a
`client` field. Since `sandboxClient` implements `SandboxInterface`
itself, `Watch` can call `s.Get(ctx, name)` directly (like `GetLogs`
already does on line 239).

### Constructor Wiring

In `client.go`, update four constructor calls:

```go
c.exec = newExecClient(conn, c.sandboxes)    // was: newExecClient(conn)
c.tcp  = newTCPClient(conn, c.sandboxes)     // was: newTCPClient(conn)
c.files = newFileClient(conn, c.sandboxes)   // was: newFileClient(conn)
c.cfg  = newConfigClient(conn, c.sandboxes)  // was: newConfigClient(conn)
```

### Fake Client Updates

Fake clients store objects by name in their internal maps. They don't
need resolution logic because they can look up directly by name. Only
the method signatures change (sandboxID → sandboxName).
