# Implementation Plan: Core SDK (Phase 1)

**Branch**: `003-core-sdk` | **Date**: 2026-06-27 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/003-core-sdk/spec.md`

## Summary

Implement a Go SDK for OpenShell following the Kubernetes client-go sub-client pattern. The SDK provides typed interfaces for Sandbox, Provider, Exec, File, and Health operations, with idiomatic Go domain types, typed errors, and a Watch interface. Proto-generated types are isolated behind internal conversion functions. Phase 1 covers ~20 RPCs across 5 sub-clients.

**Structure Decision**: The `openshell/v1/` package is the public API surface. Sub-client implementations are in separate `*_client.go` files to keep interface definitions (types) separate from implementations. Internal packages prevent consumers from importing conversion or gRPC details. The existing stub `openshell/client.go` will be removed and replaced by the v1 package.

## Implementation Phases

### Phase A: Foundation (errors, types, options, converter utilities)

Build the shared infrastructure that all sub-clients depend on:
1. Error types and Is* helpers (errors.go)
2. Shared types: SandboxPhase, EventType, StreamType (types.go)
3. Options structs (options.go)
4. Auth interface + NoAuth/StaticToken (auth.go)
5. Logger interface (logger.go)
6. Converter utilities: timestamp, error mapping (internal/converter/)
7. gRPC connection setup (internal/grpc/)
8. Client struct, NewClient, Close, ClientInterface (client.go)

### Phase B: Health + Provider sub-clients

Simplest sub-clients first to establish the pattern:
1. HealthInterface + implementation (health.go, health_client.go)
2. Health converter (trivial)
3. Provider types + interface (provider.go)
4. Provider converter (internal/converter/provider.go)
5. ProviderInterface implementation including Ensure (provider_client.go)

### Phase C: Sandbox sub-client + Watch

The largest sub-client with the most complex types:
1. Sandbox types + interface (sandbox.go)
2. Sandbox converter (internal/converter/sandbox.go)
3. SandboxInterface implementation: CRUD + AttachProvider/DetachProvider/ListProviders (sandbox_client.go)
4. WatchInterface[T] + watcher implementation (watch.go)
5. Sandbox.Watch implementation
6. Sandbox.WaitReady implementation (poll or watch-based)

### Phase D: Exec sub-client

Streaming RPCs with three execution modes:
1. Exec types + interface (exec.go)
2. Exec converter (internal/converter/exec.go)
3. ExecInterface.Run implementation (collect server-stream into ExecResult)
4. ExecInterface.Stream implementation (ExecStream wrapping server-stream)
5. ExecInterface.Interactive implementation (bidirectional stream wrapping)

### Phase E: File sub-client

File transfer via internal SSH session:
1. FileInterface (file.go)
2. File implementation using CreateSshSession internally (file_client.go)
3. Upload and Download methods

### Phase F: Integration + cleanup

1. Remove old stub `openshell/client.go` and `openshell/client_test.go`
2. Update CLAUDE.md agent context
3. Package doc.go with usage examples
4. Verify `make ci` passes
5. Integration test stubs (tagged `//go:build integration`)

## Testing Strategy

**Unit tests**: Each sub-client is tested against an in-process mock gRPC server. The mock server implements the `openshellv1.OpenShellServer` interface with canned responses. Tests verify:
- Happy path: correct SDK types returned from proto responses
- Error path: gRPC errors mapped to correct StatusError codes
- Edge cases: nil responses, empty lists, cancelled contexts

**Mock server setup**: A shared test helper creates an in-process gRPC server with bufconn (no real network). Each test registers handler functions for the RPCs it needs.

**Integration tests**: Stub files with `//go:build integration` tag. These require a running gateway and are not run by `make test`.

## Key Design Decisions

1. **NewClient over Dial**: The spec says `NewClient(config)` not `Dial(address)`. This matches client-go's `kubernetes.NewForConfig(restConfig)` and gives us a Config struct for all connection parameters.

2. **Options structs over functional options**: The brainstorm chose Options structs over functional options for client-go familiarity. Empty options structs (CreateOptions, DeleteOptions) exist for forward compatibility.

3. **Generic Watch**: `WatchInterface[T]` uses Go generics (1.18+) so the same watch pattern works for any future resource type (Phase 2 services, etc.).

4. **Ensure is client-side**: No upsert RPC exists in the proto. Ensure is Get + Create/Update implemented in the SDK, not a server-side operation.

5. **File transfer via SSH**: No dedicated file transfer RPC exists. The SDK uses CreateSshSession internally for Upload/Download, hiding the SSH mechanism from consumers.
